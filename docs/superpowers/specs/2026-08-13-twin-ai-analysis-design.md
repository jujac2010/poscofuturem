# Twin AI 실시간 분석 기능 설계

## 목표

현재 ECU 더미데이터와 지게차 운행기록을 하나의 로컬 분석 엔진에서 평가해, 우측 Twin AI 패널과 자연어 질문, 이상 원인 분석, 운행기록 요약, 자동 상세 진단 리포트를 제공한다.

실제 LLM API 없이 강의실 시연이 가능해야 하며, 이후 API 기반 분석으로 교체할 수 있도록 분석 인터페이스를 분리한다.

## 범위

### 포함

- 우측 Twin AI 분석 결과 패널
- “현재 가장 위험한 장비는?”을 포함한 자연어 질문 입력
- 랜덤 이상상황 발생 직후 원인·위험도·조치 분석
- 실시간 운행기록 요약
- 선택 장비 및 전체 장비 상세 진단 리포트 자동 생성
- 모바일 화면에서 패널이 세로로 배치되는 반응형 UI

### 제외

- 외부 LLM API 호출
- 실제 ECU 연결 및 서버 저장
- 분석 결과의 영구 저장

## 분석 구조

`EcuSnapshot`과 운행기록을 `TwinAiAnalyzer`에 전달한다. 분석기는 기존 `evaluateDiagnostic` 결과를 재사용해 장비별 위험도를 계산하고, 결과를 다음 네 가지 형식으로 제공한다.

1. `answerQuestion(question, context)`
2. `analyzeIncident(forklift, diagnostic)`
3. `summarizeDrivingRecords(records, forklifts, events)`
4. `buildFleetReport(forklifts, snapshots, records, events)`

분석 결과는 문자열만 반환하지 않고, 제목·요약·근거·권고·위험 장비 ID를 가진 구조화된 객체로 반환한다. 따라서 UI는 동일한 분석 결과를 카드, 로그, 모달에 재사용할 수 있다.

## 자연어 질문 처리

질문을 키워드 기반으로 분류한다.

- `위험`, `가장 위험`, `위험한 장비`: 위험 점수 내림차순 장비 반환
- `상태`, 특정 장비 ID: 해당 장비 진단 결과 반환
- `정비`, `점검`: 점검·위험·긴급 장비와 권고 반환
- `운행`, `기록`, `요약`: 운행기록 요약 반환
- `전체`, `리포트`, `진단`: 전체 분석 리포트 반환
- 분류되지 않은 질문: 사용 가능한 질문 예시 안내

## Twin AI 패널 UI

- 헤더: `TWIN AI ANALYSIS`, 실시간 연결 상태
- 현재 최고 위험 장비 카드
- 분석 요약 및 근거
- 원인·권고 목록
- 자연어 질문 입력창과 실행 버튼
- 최근 질문/응답 한 건
- 랜덤 이상상황 발생 시 자동 갱신되는 분석 배지

## 상세 진단 리포트

기존 선택 장비 리포트를 확장한다.

- 선택 장비 또는 전체 장비
- 위험도 점수와 등급
- 센서 현재값
- 감지된 이상 징후
- 추정 원인
- 정비 권고
- 운행기록 요약
- AI 종합 의견
- 분석 기준: 더미 학습 프로필 기반 시연용 평가

## 데이터 흐름

`ECU polling → snapshot state → diagnostic evaluator → Twin AI analyzer → panel/report`

이상상황 버튼은 기존 지게차 상태를 변경한 뒤 같은 분석 흐름을 다시 실행한다. 별도 임시 데이터나 하드코딩된 리포트 문장을 사용하지 않는다.

## 오류 및 접근성

- 빈 질문은 실행하지 않고 안내문을 표시한다.
- 존재하지 않는 장비 질문은 장비 목록을 안내한다.
- 분석 실패 시 마지막 정상 분석 결과를 유지하고 오류 메시지를 표시한다.
- 입력창과 버튼은 키보드로 사용할 수 있어야 한다.
- 위험도 색상 외에 등급 텍스트와 점수를 함께 표시한다.

## 검증 기준

- P-04호 또는 이상상황 장비가 위험 장비로 반환되는가?
- “현재 가장 위험한 장비는?” 질문에 장비명·점수·근거가 표시되는가?
- 랜덤 이상상황 발생 후 Twin AI 분석이 갱신되는가?
- 운행기록 요약이 현재 기록 수와 상태를 반영하는가?
- 전체 리포트가 모든 장비의 진단 결과를 포함하는가?
- 모바일 레이아웃에서 우측 패널이 화면 밖으로 밀리지 않는가?
