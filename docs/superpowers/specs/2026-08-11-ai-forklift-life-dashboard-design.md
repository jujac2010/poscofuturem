# AI 지게차 수명예측 대시보드 설계

## 1. 목적

발표·심사위원이 짧은 시간 안에 다음 메시지를 이해하도록 돕는 단일 페이지 프로토타입을 만든다.

> 지게차별 잔여수명을 예측해 교체 시점을 최적화하면, 계획정비 전환과 생산중단 리스크 감소를 동시에 달성할 수 있다.

이 사이트는 실제 설비 데이터 연동이나 운영 인증을 포함하지 않는다. 대신 실제 서비스로 확장 가능한 화면 구조와, 문제 정의부터 의사결정까지의 흐름을 시각적으로 보여주는 것을 성공 기준으로 한다.

## 2. 대상 사용자와 성공 기준

- 대상: 발표·심사위원
- 1차 성공 기준: 첫 화면에서 문제, AI 예측 결과, 기대효과를 30초 안에 파악할 수 있다.
- 2차 성공 기준: 특정 차량을 선택했을 때 잔여수명 추정의 근거가 데이터 항목으로 설명된다.
- 3차 성공 기준: 화면이 발표 자료처럼 보이면서도 대시보드로서 실제 상호작용이 가능하다.

## 3. 추천 접근 방식

발표형 요약과 운영형 상세를 결합한 혼합형 대시보드로 구현한다.

- 상단과 첫 번째 화면 영역은 발표형이다. 핵심 수치와 메시지를 우선한다.
- 차량별 위험도·잔여수명 목록은 운영형이다. 구체적인 판단 대상을 보여준다.
- 상세 패널은 클릭 시 열리며, 발표 흐름을 방해하지 않으면서 근거 데이터를 제공한다.

## 4. 화면 구성

### 4.1 헤더

- 브랜드/제품명: `AI Forklift Life Prediction`
- 보조 문구: `예측 기반 교체 시점 최적화`
- 상태 배지: `LIVE MODEL · 2026.08.11 09:30`
- 발표용 부제: `고장 이후 대응에서, 교체 시점 최적화로`

### 4.2 핵심 지표 카드

네 개의 지표를 한 줄로 배치한다.

1. 관리 차량: `24대`
2. 평균 잔여수명: `47일`
3. 30일 내 교체 권고: `3대`
4. 예상 비용 절감: `₩28.4M`

각 카드는 작은 변화량 또는 설명 문구를 함께 보여준다. 숫자는 현실적인 데모 데이터이며, 실제 데이터가 아님을 별도 문구로 표시한다.

### 4.3 메인 예측 시각화

- 섹션 제목: `차량별 잔여수명 예측`
- 가로 막대 차트에서 차량을 잔여수명 오름차순으로 정렬한다.
- 위험도는 앰버/레드, 관찰 대상은 블루, 안정 상태는 청록 계열로 표시한다.
- 각 행에 차량 ID, 구역, 잔여수명, 신뢰도, 상태 태그를 배치한다.
- 클릭하면 해당 차량이 선택되고 상세 패널이 갱신된다.

### 4.4 긴급 차량 강조 카드

최우선 차량을 별도 카드로 강조한다.

- 차량: `FL-07`
- 권고: `교체 검토 D-18`
- 위험도: `HIGH`
- 주요 영향 요인: 진동 +32%, 사용시간 8,420h, 최근 정비 126일 전
- CTA: `예측 근거 보기`

### 4.5 데이터에서 의사결정까지의 흐름

가로형 5단계 흐름으로 구성한다.

`운행·센서 데이터` → `정비 이력 결합` → `특징량 전처리` → `잔여수명 예측` → `교체 시점 결정`

각 단계에는 짧은 설명을 붙이고, 마지막 단계는 앰버색으로 강조한다. 이것이 심사위원에게 AI 모델 자체보다 의사결정 가치가 중요하다는 점을 전달한다.

### 4.6 기대효과

세 개의 결과 카드를 배치한다.

- 계획정비 전환: 고장 후 대응을 사전 정비로 전환
- 교체 시점 최적화: 사용 가능한 부품을 너무 일찍 교체하지 않음
- 생산중단 리스크 감소: 갑작스러운 고장으로 인한 라인 중단 예방

## 5. 상세 상호작용

- 차량 행/카드를 클릭하면 우측 상세 패널이 열린다.
- 상세 패널에는 잔여수명, 신뢰도, 위험도, 주요 영향 요인, 최근 정비 이력, 권고 조치가 표시된다.
- 닫기 버튼과 `Esc` 키로 패널을 닫을 수 있다.
- 모바일에서는 상세 패널이 화면 하단 시트처럼 동작한다.
- 필터는 초기 버전에서 추가하지 않는다. 발표 흐름을 단순하게 유지하기 위해 정렬된 전체 목록만 제공한다.

## 6. 데이터와 상태

초기 버전은 정적 데모 데이터로 구성한다.

- 차량 8대 이상을 사용해 위험도와 잔여수명 차이가 분명하게 보이도록 한다.
- 데이터 필드: 차량 ID, 구역, 잔여수명, 신뢰도, 위험도, 사용시간, 진동 변화, 적재량, 최근 정비 일수, 권고 조치
- 예측 모델 API는 만들지 않는다. 대신 화면에 `Random Forest / XGBoost 기반 데모 모델`이라는 설명을 제공한다.
- 예측값은 UI 상태에서 관리하고, 선택 차량만 상호작용으로 변경한다.

## 7. 시각 및 접근성 원칙

- 짙은 네이비 배경과 밝은 패널 대비를 사용한다.
- 전기 블루를 기본 강조색, 앰버와 레드를 위험 상태색으로 사용한다.
- 색상만으로 상태를 구분하지 않고 텍스트 태그와 아이콘 대체 문구를 함께 제공한다.
- 작은 설명 텍스트의 대비를 충분히 확보한다.
- 카드와 버튼은 키보드 포커스를 볼 수 있어야 한다.
- 차트 막대에는 실제 텍스트 값도 함께 표시한다.

## 8. 구현 범위와 검증

### 포함

- 단일 반응형 페이지
- 데모 데이터 기반 지표, 차트, 흐름, 기대효과
- 차량 선택 및 상세 패널 인터랙션
- 발표용 문구와 제품 메타데이터

### 제외

- 실시간 센서 수집
- 로그인, 권한, 외부 API
- 데이터베이스와 파일 업로드
- 실제 ML 학습·추론 파이프라인

### 검증

- 프로덕션 빌드가 성공해야 한다.
- 데스크톱과 좁은 화면에서 레이아웃이 깨지지 않아야 한다.
- 차량 선택, 패널 닫기, 키보드 `Esc` 동작이 작동해야 한다.
- 첫 화면만 보아도 핵심 메시지와 최우선 차량을 이해할 수 있어야 한다.
